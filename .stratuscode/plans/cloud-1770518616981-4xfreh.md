# Mobile Arrow Control UI Overflow Fix

## Summary
The mobile D-pad controls in GameCanvas.tsx are overflowing into the game canvas on certain screen sizes, blocking part of the game. The current implementation uses `min(16vw, 80px)` for button sizing which doesn't account for the available vertical space.

## Current Issue
- D-pad buttons use `min(16vw, 80px)` for width/height
- Grid has 3 rows with gaps of `min(2vw, 12px)`
- Positioned at `bottom: 'min(4vw, 24px)'`
- On certain viewport sizes, the D-pad can overlap the bottom portion of the 13-row game grid

## Proposed Solution
Constrain the D-pad sizing to fit within available space below the game content without overlapping:

1. **Add a safe container** with max-height constraint based on available viewport space
2. **Use CSS custom properties** to calculate button size dynamically
3. **Scale buttons proportionally** within the constrained space

## Implementation Details

### Changes to `src/components/GameCanvas.tsx`:

1. Wrap the D-pad in a container with height constraints
2. Replace fixed `min(16vw, 80px)` sizing with calculations based on available space
3. Use CSS `clamp()` or calculated values to ensure buttons fit within:
   - Available viewport height minus game grid height
   - Safe margin from game content
   - Maximum touch-friendly size (44px minimum for accessibility)

### Sizing Strategy:
- Calculate max available height for D-pad based on viewport
- Size buttons as `min(availableHeight/3.5, 12vw, 70px)` to ensure they fit
- Ensure minimum 44px touch target for accessibility
- Maintain 3x3 grid layout with proportional gaps
